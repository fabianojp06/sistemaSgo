
UC04.01 — Disbursement Schedule
Read-Only Reactive View — List | Print | Export


Identification and Conditions


Epic / Module
EP48/26 — Budget Module
Calculation Engine
TotalizerService (synchronous backend)
Guidelines
[SHIELDED ORIGIN] | [ERROR LOCK] | [ATOMIC SYNCHRONISM]
Classes Involved
Proposta, VersaoProposta, Meta, ContaAnalitica (N7), TotalizerService, HistoricodeOperacoes


Actors Involved
Common User, Budget Analyst, Auditor, SGO System (Schedule Engine)
Pre-Conditions
• User authenticated and active in SGO 2.0
• Profile with active read access to the Budget menu > Disbursement Schedule
• Master Commercial Proposal with an active budget version saved in physical tables
Post-Conditions
• Disbursement Schedule time matrix generated and rendered on screen
• Document exported as .XLSX and structured PDF
• Operation recorded in the central HistoricodeOperacoes trail


Acceptance Criteria — BDD/Gherkin


Scenario 1 — Successful Schedule generation    ✅ HAPPY PATH  
Given
the user is authenticated with read access to the Budget menu > Disbursement Schedule
And
there is a Commercial Proposal with an active version and registered analytical financial appropriations
When
the user selects the Partnership Agreement (required), sets the optional filters (Goal, Version, Attachment) and triggers [Generate Schedule]
Then
the TotalizerService is triggered on the backend and automatically distributes the personnel and travel installments month by month
And
the time matrix is rendered on screen with columns: Event | Date | Description | Monthly Disbursement (R$) | Accumulated Disbursement (R$) | Accumulated Financial % (%) | Amount Transferred every 12 months (R$)
And
all numeric fields are in Read-Only mode — no manual input is allowed [SHIELDED ORIGIN]
And
the operation is recorded in HistoricodeOperacoes with the operator ID, timestamp and a snapshot of the filters


Scenario 2 — Filtering by Goal and displaying the "All" label    ✅ HAPPY PATH  
Given
the user accesses the Disbursement Schedule filter panel
When
the user leaves the [Goal] field blank and triggers [Generate Schedule]
Then
the system displays the label "All" in the Goal field of the generated report's header — never a null value [RN0250]
And
the matrix displays consolidated data for all Goals of the selected proposal


Scenario 3 — Attachment concatenation in the header (RN0259)    ✅ HAPPY PATH  
Given
the user fills in the [Attachment] field in the filter panel
When
the system generates the report
Then
the content of the Attachment field is concatenated to the title "DISBURSEMENT SCHEDULE" in the header of the generated document [RN0259]
And
the concatenation format follows the standard defined by André (to be validated — GAP-UC0401-003)


Scenario 4 — Accumulated Financial % calculation (RN0252)    ✅ HAPPY PATH  
Given
the time matrix is being generated for a proposal with a defined Global Value
When
the TotalizerService calculates the Accumulated Financial % field for each row
Then
the value is calculated as: (row's Accumulated Disbursement / Proposal's Total Global Value) × 100
And
the result is displayed with exactly 2 fixed decimal places (e.g., 61.14%) — Half-Even banker's rounding [RN0252]


Scenario 5 — "Amount Transferred every 12 months" column (RN0253)    ✅ HAPPY PATH  
Given
the proposal spans multiple years
When
the system generates the time matrix rows
Then
only in the rows corresponding to months 12, 24, 36, 48... does the "Amount Transferred every 12 months" field display the sum for the annual cycle
And
in the remaining intermediate rows, the cell stays empty or shows a dash (–) [RN0253]


Scenario 6 — Automatic annual break row (RN0254)    ✅ HAPPY PATH  
Given
the time matrix is being rendered
When
each 12-month cycle of the term ends
Then
the TotalizerService automatically injects a Tfoot row with the annual subtotals of the columns: Monthly Disbursement, Accumulated Disbursement and Accumulated Financial % [RN0254]


Scenario 7 — Export to PDF and XLSX    ✅ HAPPY PATH  
Given
the time matrix is rendered on screen
When
the user triggers [Print] or [Export]
Then
[Print] generates a structured PDF via UC0.05 with header, footer "DISBURSEMENT SCHEDULE" and page numbering
And
[Export] generates an .XLSX file via UC0.06 preserving the matrix structure, the applied filters and the annual breaks
And
the operation is recorded in HistoricodeOperacoes [RN0232]


Scenario 8 — Block — Proposal without financial data (Flow E1)    🔴 ERROR SCENARIO  
Given
the user selects a Partnership Agreement
When
the TotalizerService returns a Global Value of R$ 0.00 or no analytical records
Then
the compilation is aborted and the month grid is NOT opened
And
the system displays the alert: "Operation Rejected: The selected Proposal has no financial data registered for consolidation." [ERROR LOCK]
And
no data is persisted and no PDF/XLSX is generated


Scenario 9 — Block — Partnership Agreement not selected    🔴 ERROR SCENARIO  
Given
the user accesses the filter panel
When
the user triggers [Generate Schedule] with the Partnership Agreement field blank
Then
the system blocks processing and displays: "Select a Partnership Agreement to continue."
And
the screen remains active with the other filters intact [ERROR LOCK]


Scenario 10 — Cancel the operation (Flow A1)    🟡 ALTERNATIVE  
Given
the user is on the Schedule's parameters and filters screen
When
the user triggers [Cancel]
Then
the system stops any scan in progress, clears the interface's temporary memory
And
returns to the screen's initial state without generating files and without recording the operation in the audit trail


Applicable Business Rules


Code
Business Rule Description
RN_CD_001
Description Immutability — manual input is prohibited in installment description cells. The entire descriptive tree is generated automatically by the server.
RN_CD_002
Redistribution Lock — the sum of all distributed columns must match exactly the Total Cost managed by the TotalizerService.
RN_CD_003
Temporal Compliance — rejects matrices whose range exceeds the Commercial Proposal's start and end date limits.
RN0200
Parameter Sampling — if "Show filters = Yes," the search criteria must be displayed at the top of the printed report.
RN0250
Empty Goal Handling — a blank Goal filter compulsorily displays the string "All" in the header. Null value prohibited.
RN0251
Accumulated Disbursement — progressive vertical sum of the Monthly Disbursement, row by row, in chronological order.
RN0252
Accumulated Financial % — (Accumulated Disbursement / Total Global Value) × 100, locked to 2 fixed decimal places. Half-Even rounding.
RN0253
12-Month Cycle Transfer — sum of the annual cycle displayed only in months 12, 24, 36... Remaining cells: empty or dash.
RN0254
Annual Subtotals — TotalizerService automatically injects a Tfoot row at the end of every 12 months with per-column subtotals.
RN0259
Attachment Concatenation — if the Attachment field is filled in, its content is concatenated to the title in the document's header.
